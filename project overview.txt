PROJECT OVERVIEW - BUNDACARE WHATSAPP BOT

Ringkasan
bundacare adalah bot WhatsApp berbasis Node.js yang mengingatkan ibu hamil
minum tablet tambah darah (FE) setiap hari. Bot mencatat jawaban "Sudah" atau
"Belum", dan menyediakan dashboard admin web untuk melihat data user, log
pengingat, serta export CSV.

Tech Stack
- Runtime: Node.js
- WhatsApp integration: whatsapp-web.js + LocalAuth
- Web server admin: Express
- Database: SQLite melalui sqlite3
- Tanggal dan waktu: Luxon, timezone Asia/Jakarta
- QR login WhatsApp: qrcode-terminal

Struktur Project
- index.js
  File utama. Berisi konfigurasi, daftar pertanyaan onboarding, helper
  parsing/validasi, akses database, handler pesan WhatsApp, handler poll, loop
  scheduler, command admin WhatsApp, dan admin web.
- package.json
  Script utama: npm start dan npm test.
- tests/
  Unit test untuk parsing, validasi waktu, retry backoff, alur reminder,
  pencatatan vote poll, jendela kirim, dan panel admin.
- data/bundacare.db
  Database SQLite runtime. File ini dibuat/dipakai saat aplikasi berjalan.
- data/admin_web_password.txt
  Password admin web yang dibuat otomatis jika ADMIN_WEB_PASSWORD tidak diset.
  Isi file ini sensitif dan tidak perlu dicantumkan di dokumentasi/log.
- .wwebjs_auth dan .wwebjs_cache
  Data session/cache WhatsApp Web lokal.
- daftar-fitur-flow-trigger.txt
  Dokumentasi fitur, trigger, dan flow.
- data backup/bundacare.db
  Backup database.

Cara Menjalankan
1. Install dependency:
   npm install
2. Jalankan bot:
   npm start
3. Scan QR WhatsApp yang muncul di terminal.
4. Dashboard admin berjalan di:
   http://localhost:3030/admin

Script
- npm start
  Menjalankan index.js.
- npm test
  Menjalankan seluruh tes di folder tests/.

Flow Runtime Utama
1. Aplikasi start.
2. Folder data dipastikan ada.
3. Database SQLite dibuka di data/bundacare.db.
4. Tabel dan kolom database dibuat/dimigrasi otomatis.
5. Admin web Express dijalankan jika ADMIN_WEB_ENABLED tidak bernilai 0/false.
6. Client WhatsApp Web dibuat dengan LocalAuth.
7. Jika session belum ada, QR ditampilkan di terminal.
8. Saat WhatsApp ready, bot mulai menerima pesan dan vote poll.
9. Scheduler reminder berjalan setiap 30 detik.
10. Scheduler mengambil user aktif, allowed, tidak blocked, punya reminder_time,
    lalu mengirim pengingat tablet FE harian.

Database
1. users
   Menyimpan profil user, status onboarding/active/paused/completed, pengaturan
   reminder, flag admin/allowed/blocked, dan state poll FE.

2. reminder_logs
   Menyimpan log harian pengingat FE per user dan tanggal. Jawaban dicatat
   sebagai "Sudah" atau "Belum", termasuk counter masing-masing jawaban.

Konfigurasi Environment Penting
- ENFORCE_ALLOWLIST
  Jika true/1, nomor user harus ada di allowlist atau admin.
- ADMIN_WA_IDS
  Daftar wa_id admin WhatsApp.
- ALLOWLIST_WA_IDS
  Daftar wa_id yang diizinkan saat allowlist aktif.
- RATE_LIMIT_MAX_PER_MINUTE
  Batas pesan/vote per menit. Default 20.
- RATE_LIMIT_WINDOW_MS
  Window rate limit. Default 60000 ms.
- RATE_LIMIT_COOLDOWN_MS
  Durasi cooldown rate limit. Default 120000 ms.
- POLL_MAX_RESPONSES_PER_DAY
  Batas jawaban poll per jenis jawaban per hari. Default 2.
- ADMIN_WEB_ENABLED
  Admin web aktif secara default. Set 0/false untuk mematikan.
- ADMIN_WEB_PORT
  Port admin web. Default 3030.
- ADMIN_WEB_USER
  Username admin web. Default admin.
- ADMIN_WEB_PASSWORD
  Password admin web dari env. Jika kosong, sistem memakai/membuat file
  data/admin_web_password.txt.
- ADMIN_WEB_SESSION_TTL_MS
  Masa berlaku session admin web. Default 8 jam.
- ADMIN_WEB_COOKIE_SECURE
  Cookie secure untuk admin web. Aktif otomatis saat NODE_ENV=production.
- REMINDER_LOG_RETENTION_DAYS
  Retensi log reminder harian. Default 180 hari.
- POLL_RETRY_BASE_DELAY_MS
  Delay dasar retry poll. Default 5 menit.
- POLL_RETRY_MAX_DELAY_MS
  Batas maksimal delay retry poll. Default 30 menit.
- REMINDER_LOOP_CONCURRENCY
  Jumlah user yang diproses paralel per batch scheduler. Default 10.
- PUPPETEER_EXECUTABLE_PATH
  Path browser Chromium/Chrome/Edge jika ingin menentukan manual.
- PUPPETEER_NO_SANDBOX atau DISABLE_CHROME_SANDBOX
  Menonaktifkan sandbox Chromium jika dibutuhkan environment server.

Flow User Baru dan Onboarding
Trigger:
- Nomor baru mengirim start atau mulai di chat private.
- Pesan dari grup, status, dan target direct unsupported diabaikan.
- Jika allowlist aktif, nomor harus allowed atau admin.

Alur:
1. Bot membuat record user dengan status onboarding.
2. Bot mengirim pertanyaan onboarding pertama.
3. User menjawab pertanyaan secara berurutan.
4. Jawaban divalidasi sesuai tipe data.
5. Jika user menolak diingatkan oleh bundacare, status menjadi active tetapi
   reminder_time dikosongkan dan reminder tidak aktif.
6. Jika onboarding selesai, status menjadi active, reminder_time tersimpan, dan
   bot mengirim konfirmasi jadwal reminder.

Pertanyaan Onboarding
1. Nama ibu.
2. Usia.
3. Kehamilan ke berapa.
4. Apakah rutin mengonsumsi obat.
5. Apakah masih mengonsumsi teh.
6. Siapa yang biasanya mengingatkan minum obat.
7. Apakah mau diingatkan bundacare.
8. Jam reminder harian.

Flow Pesan Pembuka
Trigger:
- Nomor baru mengirim pesan apa pun selain start/mulai.

Alur:
1. Bot mengirim perkenalan singkat bundacare.
2. Bot meminta user mengetik start.
3. User belum masuk onboarding sebelum mengirim start/mulai.

Flow Reminder Harian Tablet FE
Trigger:
- Scheduler 30 detik.
- User status active, allow_remindcare=1, tidak blocked, punya reminder_time.
- Waktu sekarang sudah mencapai reminder_time.
- Pengingat hari ini belum dikirim.

Alur:
1. Bot mengirim teks pengingat harian (sekali per hari).
2. Bot mengirim poll "Sudah minum tablet FE hari ini?".
3. Bot menyimpan last_reminder_date dan last_poll_message_id.
4. Bot membuat/ensure reminder_logs untuk tanggal tersebut.
5. Setelah hari program melewati poll_days_limit (default 14), hari ganjil hanya
   mengirim teks tanpa poll.
6. Jika pengiriman poll gagal, fail_count dan last_attempt_at diupdate untuk
   retry dengan exponential backoff.

Flow Jawaban Reminder FE
Trigger:
- User membalas teks yang bisa diparse sebagai "Sudah" atau "Belum".
- Atau user vote pada poll FE aktif.
- Vote yang terlewat (bot sempat mati) dipulihkan lewat rekonsiliasi tiap 5 menit.

Alur:
1. Bot memastikan poll/log hari ini relevan.
2. Jawaban dicatat ke reminder_logs.
3. Counter response_sudah_count atau response_belum_count dinaikkan.
4. Jika batas jawaban harian sudah tercapai, bot memberi tahu user agar tidak
   mengirim ulang.
5. Jika jawaban "Sudah", bot mengirim terima kasih.
6. Jika jawaban "Belum", bot mengingatkan untuk minum tablet.

Command User
- start / mulai
  Mengaktifkan reminder. Jika jam belum ada, user diarahkan mengisi jam.
- stop / berhenti
  Menjeda reminder dan mengubah status menjadi paused.
- ubah jam 17:00 / set jam 17:00 / jam 17:00
  Mengganti reminder_time dan mengaktifkan reminder.
- help / menu
  Menampilkan daftar perintah.
- info / informasi
  Menampilkan ringkasan profil, status pengingat tablet FE, dan catatan harian.
- edit
  Menampilkan menu edit.
- edit data
  Reset data profil dan mulai onboarding dari awal. Perlu konfirmasi dua kali
  dalam 5 menit.
- delete / hapus
  Hapus akun dan reminder_logs. Perlu konfirmasi dua kali dalam 5 menit.
- batal
  Membatalkan konfirmasi edit/hapus.
- about
  Menampilkan info singkat project.
- website
  Menampilkan alamat website.

Command Admin WhatsApp
Syarat:
- User harus punya is_admin=1. Admin bisa diset melalui ADMIN_WA_IDS.

Daftar command:
- admin help
  Menampilkan command admin.
- admin stats
  Menampilkan statistik total user, active, allowed, dan blocked.
- admin allow <wa_id>
  Mengizinkan nomor.
- admin block <wa_id>
  Memblokir nomor.
- admin unblock <wa_id>
  Membuka blokir nomor.
- admin purge logs <hari>
  Menghapus reminder_logs yang lebih lama dari jumlah hari tertentu.

Admin Web Dashboard
URL:
- /admin/login
- /admin/auth (tautan masuk dari email)
- /admin

Autentikasi:
- Username default: admin.
- Password dari ADMIN_WEB_PASSWORD jika ada.
- Jika env kosong, password dibaca/dibuat di data/admin_web_password.txt.
- Magic link email sekali pakai: GET hanya memeriksa tautan, POST yang memakai
  token, sehingga prefetch email tidak menghanguskan tautan.
- Session disimpan in-memory menggunakan cookie rc_admin.

Endpoint API Admin:
- GET /admin/api/summary
- GET /admin/api/users
- GET /admin/api/users/:waId
- GET /admin/api/logs
- GET /admin/api/export/users.csv
- GET /admin/api/export/reminder_logs.csv
- GET /admin/api/users/:waId/export.csv

Isi Dashboard:
- Summary user dan jawaban hari ini.
- Daftar user.
- Detail user.
- Riwayat pengingat FE.
- Export CSV untuk analisis data.

Proteksi dan Mekanisme Operasional
- Private chat only: grup dan status diabaikan.
- Allowlist optional melalui ENFORCE_ALLOWLIST.
- Blocklist user melalui admin command.
- Rate limit pesan/vote per user.
- Konfirmasi dua kali untuk aksi edit data dan delete.
- Retry poll dengan exponential backoff.
- Cleanup reminder_logs otomatis sekali per hari.
- Migration kolom/tabel otomatis saat startup.
- Admin web memakai header keamanan dasar:
  X-Frame-Options, X-Content-Type-Options, dan Referrer-Policy.

Catatan Teknis
- index.js saat ini bersifat monolith. Semua logic bot, database, admin web,
  dan scheduler berada di satu file.
- Database dan session WhatsApp bersifat lokal. Backup perlu dilakukan dari
  data/bundacare.db dan folder session jika ingin memindahkan server.
- Jangan membagikan isi data/admin_web_password.txt.
- Jika admin web dipakai di production, sebaiknya set ADMIN_WEB_PASSWORD via
  environment variable dan jalankan di balik HTTPS/reverse proxy.
- Karena whatsapp-web.js bergantung pada WhatsApp Web, runtime membutuhkan
  browser Chromium/Chrome/Edge yang bisa dijalankan oleh Puppeteer.
